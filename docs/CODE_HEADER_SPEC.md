# 程式檔頭與 NOTE 規範

> 檔案路徑：`docs/CODE_HEADER_SPEC.md`
> 版本：v1.0（2026-08-19）
> 適用範圍：本 repo 內**所有**原始檔（`*.py`、`*.ps1`）。設定檔（`*.json`、`*.toml`、`*.yml`）不適用，JSON 沒有註解語法；YAML 與 TOML 可寫但不強制。
> 語言：一律繁體中文。路徑、程式識別字、CLI 指令、環境變數名保留英文。

本規範管兩件事，而且**刻意分開**：

| 載體 | 回答什麼 | 在哪 |
|---|---|---|
| **十欄檔頭** | 這支程式**怎麼維護** | 每個原始檔的開頭 |
| **`NOTE(NOTE-NNN)`** | 這行程式**為什麼要成立** | 程式中標號，內容在 [`docs/NOTES.md`](NOTES.md) |

**檔頭不寫決策理由，決策理由不寫檔頭。** 混在一起的結果是：檔頭長到沒人讀，而真正需要理由的那三行藏在第 40 行。

---

## 一、十欄檔頭

欄位順序固定，缺一不可：

```python
# Dev Triangle MCP source maintenance contract
# 上下游: 誰呼叫本檔、讀寫哪些資料、結果流向何處
# 檔案路徑: dev-triangle-mcp/path/to/file.py
# 產生時間: 2026-08-19 10:30 +08:00
# 版本: v1.0
# 功能說明: 這支程式實際在做什麼（白話；看完不必讀碼就懂它的功能）
# 模組定位: 它在架構中是什麼、以及「不是」什麼（邊界）
# 主要責任:
#   1. 編號列舉具體職責，點到函式名
#   2. ...
# 維護提醒:
#   - 「不得／不可」開頭的禁令，以及刻意的取捨與其理由
#   - 與版本綁定，例如「v1.2 新增 …」
# 驗證方式:
#   - 可直接貼上執行的指令
# ------------------------------------------------------------
```

PowerShell 檔用同樣的 `#` 註解形式，放在 `<# .SYNOPSIS #>` 說明區塊**之後**、`param()` 之前。

### 三個最容易寫糊的欄位

它們**必須分開寫**，不得合併成一段：

| 欄 | 回答 | 反例（寫糊了） |
|---|---|---|
| **功能說明** | 這支程式在幹嘛 | 「本模組提供 profile 相關功能」——講了等於沒講 |
| **模組定位** | 它在架構中的位置與邊界（**是什麼／不是什麼**） | 只寫「是 provider 層的一部分」，沒寫它不做什麼 |
| **主要責任** | 編號的職責清單，**點到函式名** | 「負責處理設定」——沒有任何函式名可以追 |

### 各欄規則

- **`檔案路徑`**：從 repo 名開始的相對路徑，例如 `dev-triangle-mcp/providers/profiles.py`。方便從貼出來的片段反查來源。
- **`產生時間`**：檔案**首次**建立這份檔頭的時間，帶 `+08:00`。不是每次改都更新——那是 `版本` 的工作。
- **`版本`**：**要真的遞增**。它是 `維護提醒` 掛載的錨點（「v1.2 新增 …」逐版累積）。整個 repo 都是 `v1.0` 等於這一欄沒寫。行為改變才升版；改錯字不升。
- **`維護提醒`**：只寫「不得／不可」開頭的禁令，以及刻意的取捨。**需要理由才成立的行為不寫在這裡**，那是 `NOTE(NOTE-NNN)` 的工作，這裡最多留一行指過去。
- **`驗證方式`**：必須指向**真實存在**的測試檔或可直接執行的指令。這是十欄裡唯一可被執行、可被打臉的一欄；一旦失效，整份檔頭的可信度就沒了。由 `tests/test_repo_integrity.py` 機械檢查。

### 選配欄位

複雜檔案建議補（放在 `主要責任` 之後）：

```
# 輸入 -> 處理 -> 輸出 Pipeline:
# 主要匯出:
# 依賴套件:
```

### 與既有英文 docstring 的關係

`server.py` 與 `antigravity_report_server.py` 的模組 docstring 是**憲章文字**，`tests/test_charter_consistency.py` 會斷言它的措辭（見 `docs/SAI.md` `W12`）。

**處置**：十欄檔頭以 `#` 註解放在檔案**最前面**，原本的英文 docstring **原封保留**在它下面。不得為了「統一風格」把 docstring 翻成中文或刪掉——那會讓憲章一致性測試失去斷言對象。

## 二、`NOTE(NOTE-NNN)`

### 什麼時候要寫

寫下「**需要理由才成立**」的行為時：安全邊界、取消語意、競態處理、刻意不擋的失敗、看起來像 bug 但其實是刻意的寫法。

判準一句話：**如果後人把這行改掉，測試不會紅，但行為會壞——那就要 NOTE。**

### 怎麼寫

程式裡標號：

```python
# NOTE(NOTE-002): agy 的 prompt 只經 --print 傳一次，結尾不得再 append。
command_line += ["--print", prompt, "--print-timeout", timeout]
```

`docs/NOTES.md` 建同號條目，必備五欄：**決策日期／適用範圍／決策／原因／驗證**，必要時加**維護邊界**。

### 硬規則

1. 程式中的 `NOTE(NOTE-NNN):` **必須**能在 `docs/NOTES.md` 找到同號條目。禁止失效引用。
2. **一行摘要表格不算數。** 只有一行字、沒有原因也沒有驗證的條目，追過去等於沒追。
3. 號碼**不重用**。條目作廢就標「已作廢（YYYY-MM-DD，原因）」，不刪、不重編。
4. 行為改變時，**決策、測試、引用處三者同步更新**。
5. 由 `tests/test_repo_integrity.py` 機械檢查第 1 條。

---

## 驗證方式

```powershell
python -m pytest -q tests\test_repo_integrity.py
```

該測試斷言三件事：每個原始檔都有十欄檔頭且欄名齊全、檔頭 `驗證方式` 指到的檔案存在、每個 `NOTE(NOTE-NNN)` 都找得到同號條目。
